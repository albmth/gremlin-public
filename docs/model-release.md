# Model release

How the 30.8 GB of weights get to the worker without ever being in Git or the image.

## The pin

`worker/model-release.json` is generated by `tools/model_release.py pin` and holds `asset_set_sha256`, `repo` and `revision`.
The asset-set hash is over the sorted list of destination, upstream repository, revision, path, size and SHA-256 of every file the tier recipes need.
The recipes in `worker/tiers/` are the authority; a downloaded manifest can't redefine weights.
The provider `/run` input and every worker `/lease` carry the same release identity, and the API refuses a mismatch before any attempt starts.

Two modes, chosen by `IMPRINT_WEIGHT_SOURCE`:

| Mode | What the worker does | Status |
| --- | --- | --- |
| `native-cache` | RunPod fetches the pinned Hugging Face repository at its exact commit before the container starts; the worker resolves the snapshot under `/runpod-volume/huggingface-cache/hub`, hashes all eight files and hands the directory to ComfyUI | Production |
| `runtime-hf` | The worker downloads each upstream file itself into staging, hashes it and places it atomically | Fallback, not qualified since the move to native cache |

Both need `IMPRINT_ENGINE_ARGS=--fast-disk`, a 50 GB container disk and no network volume.
Every cold boot hashes every file before a job can be leased; a changed or unreadable file stops the engine.
Native mode never downloads, copies, repairs or chmods anything in the provider cache.

## Preparing a release

```sh
PYTHONPATH=worker uv run python tools/model_release.py prepare \
  --repo OWNER/IMMUTABLE_RELEASE --models-root artifacts/weights --output artifacts/release
PYTHONPATH=worker uv run python tools/model_release.py pin \
  --repo OWNER/IMMUTABLE_RELEASE --revision FULL_40_CHARACTER_COMMIT --output worker/model-release.json
docker build --platform linux/amd64 --target runtime -t gremlin-imprint:local worker
uv run python tools/check_worker_image.py gremlin-imprint:local --models-root artifacts/weights --disk-gb 50
```

`prepare` hashes the local weights, hard-links exactly the required files into ComfyUI's layout and copies the notices and a mixed-licence model card; it never contacts Hugging Face.
Upload that directory to a private repository, check every LFS size and hash against the manifest, then freeze it and pin the full commit.
`check_worker_image.py` runs the image offline as UID 10001 with real weights, confirms no model bytes are embedded and that image plus one model set plus 8 GiB scratch fit in 50 GB.

## Credentials

The worker reads the private release with `HF_TOKEN` from a RunPod secret, read-only on that one repository; publication uses a separate write-scoped token.
Tokens never enter Git, release JSON, build arguments, command lines or diagnostics; the ComfyUI child runs with the acquisition variables stripped and `HF_HUB_OFFLINE=1`.
RunPod substitutes secrets at boot, so an existing worker keeps its old value until it is replaced.

## Registering an image

A new digest goes into `control/gremlin_control/gpu_qualifications.json` as `status: trial` with empty `accepted_gpu_ids` and the GPUs to try in `trial_gpu_ids`.
Qualify on staging with `GpuQualificationEnabled=true`: one session per GPU, simple tier then complex, both fixtures compared against that GPU's accepted controls.
Only the owner's acceptance of the videos promotes it; a failed gate keeps its hold and the image stays a trial.
Never edit an accepted historical entry.

When changing the endpoint's model reference, send the full inline template with `modelReferences` in one GraphQL mutation (a bare `templateId` save fails with `Unable to access model`), keep workers at 0/0 throughout, and read the endpoint back before planning anything.
